# テスト方針

## 1. 目的

MVPのテストは、以下を確認します。

- Route HandlerがAPI仕様どおりのステータスとエラーコードを返す
- 認証・認可に関わる回帰を防ぐ
- Supabase RLSにより、所属していないリストのデータを操作できないことを確認する
- ユーザーが行う主要な画面操作を確認する

Google OAuthは外部サービスのため、単体テストではモックし、実際のログインは手動スモークテストで確認します。

## 2. コマンド

| コマンド                 | 内容                                |
| ------------------------ | ----------------------------------- |
| `pnpm lint`              | ESLintによる静的解析                |
| `pnpm exec tsc --noEmit` | TypeScriptの型チェック              |
| `pnpm test`              | VitestによるRoute Handler単体テスト |
| `pnpm build`             | Next.jsの本番ビルド検証             |

変更後は、少なくとも該当テスト、型チェック、ビルドを実行します。

```powershell
pnpm test
pnpm exec tsc --noEmit
pnpm build
```

## 3. 現在の自動テスト

テストランナーはVitestです。設定は [vitest.config.mts](/vitest.config.mts) にあり、`src/**/*.test.ts`を対象にします。

| テストファイル                                                                           | 確認内容                                                                                                                                                  |
| ---------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [items/route.test.ts](/src/app/lists/[listId]/items/route.test.ts)                       | 未認証のアイテム取得が`401 UNAUTHENTICATED`になること、無効なアイテム入力が`422 VALIDATION_ERROR`になること、所属メンバーが有効なアイテムを作成できること |
| [members/[userId]/route.test.ts](/src/app/lists/[listId]/members/[userId]/route.test.ts) | 作成者自身のメンバー除外が`409 OWNER_CANNOT_BE_REMOVED`になり、DB削除を実行しないこと                                                                     |

これらのテストでは`@/lib/api/auth`をモックします。Supabaseへ接続しないため、高速にRoute Handlerの入力検証・HTTP応答・アプリ側認可ルールを確認できます。

## 4. 手動スモークテスト

Google OAuthとSupabaseを含む環境で、リリース前に以下を確認します。

### 認証

- Google OAuthでログインできる
- ログアウト後に保護されたAPIを利用できない
- 画面を再読み込みしてもセッションが維持される

### リストとメンバー

- リスト作成後、作成者が自動的にメンバーになる
- 作成者がリスト名を変更できる
- 作成者がユーザーID指定でメンバーを追加・除外できる
- 作成者は自分自身を除外できない
- 一般メンバーは退会でき、作成者だけがリストを削除できる

### アイテム

- アイテムを追加・編集・完了・未完了に変更できる
- 未完了と完了済みを切り替えて表示できる
- 未完了アイテムは、確認ダイアログを承認した場合だけ削除できる
- 完了済みアイテムを削除すると`409 COMPLETED_ITEM_CANNOT_BE_DELETED`になる

### UI

- PCではサイドバーが常に表示される
- SPではサイドバーが閉じた状態で始まり、メニューから開閉できる
- サイドバーの背景クリックとリスト選択でサイドバーが閉じる
- アイテム追加・編集モーダルが`Esc`、背景クリック、キャンセルで閉じる
- アイテム追加・編集モーダルを開いた直後に商品名へフォーカスされる
- 商品名の必須・文字数、数量の整数・範囲バリデーションが機能する
- 完了・未完了の表示切替ではAPIを呼び出さない
- 100件を超えるアイテムがある場合も全件が取得される
- APIエラー時に楽観的な表示が巻き戻り、エラーが表示される
- 未完了アイテムの削除前に確認ダイアログが表示される
- 完了済みアイテムに削除操作が表示されない
- 右下固定の追加ボタンが未完了一覧で表示される
- 前回開いたリストが同一ブラウザで復元される
- 所属リストが0件の場合にリスト作成を促す空状態が表示される

## 5. RLS結合テスト

RLSはアプリ側認可とは独立して検証します。Supabaseの検証用プロジェクトまたはローカルSupabase環境に、少なくとも2人のテストユーザーを用意します。

| シナリオ                                             | 期待結果   |
| ---------------------------------------------------- | ---------- |
| ユーザーAが作成したリストを、未加入のユーザーBが読む | 拒否される |
| Bが加入後にアイテムを作成・更新する                  | 許可される |
| Bがメンバー追加・除外、リスト削除を行う              | 拒否される |
| AがBを除外した後、Bがアイテムを読む                  | 拒否される |

RLSテストを自動化する場合は、テスト専用のSupabaseプロジェクトを用い、本番プロジェクトや開発中の共有データを対象にしません。

## 6. E2Eテスト

E2Eテストは未導入です。導入時はPlaywrightを使い、Google OAuthそのものは自動化せず、テスト用の認証済みセッションを用意します。

最初に自動化する導線は以下です。

1. リストを作成する
2. 右下の追加ボタンからアイテムを追加する
3. アイテムを編集し、完了にする
4. 未完了へ戻し、削除確認を経て削除する
5. SP表示でサイドバーを開き、別のリストへ切り替える

## 7. 依存関係の問題

`pnpm test`や`pnpm dev`で、VitestまたはNext.jsのモジュール解決エラーが出る場合は、依存関係が途中までしか展開されていない可能性があります。

まずNode.jsのバージョンを確認します。このプロジェクトはVoltaでNode.js `24.13.0`を固定しています。

```powershell
node -v
pnpm -v
```

次に、ロックファイルを変更せず依存関係を再構築します。

```powershell
pnpm install --force
```

Vitestの設定ファイルはESMとして読み込むため、拡張子は`vitest.config.mts`を維持します。

再構築後に、テスト・型チェック・ビルドを順に実行します。

```powershell
pnpm test
pnpm exec tsc --noEmit
pnpm build
```
