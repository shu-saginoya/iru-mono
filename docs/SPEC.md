# 仕様書（MVP）

## 1. 目的

複数のユーザーで買い物リストを共有するアプリです。初回リリースでは、迷わず使える最小機能に絞ります。

- Google アカウントでログインする
- ユーザーがリストを作成する
- リストのメンバーがアイテムを共有する
- アイテムを追加・編集・完了・削除する

## 2. 基本モデル

### User

- Google アカウントで認証する
- 1 人のユーザーは複数のリストを作成・利用できる
- Google のパスワードや認証情報はアプリ DB に保存しない

### List

- ユーザーが名前を付けて作成する
- 作成者は自動的にメンバーになる
- 1 つのリストに複数ユーザーが参加できる
- 1 人のユーザーが複数リストに参加できる

### Item

- リストに所属する
- 商品名、数量、完了状態、完了日時を持つ
- 同じリストのメンバー間で共有する
- タグ、カテゴリ、優先度、担当者は初回リリースでは持たない

### ListMember

- ユーザーとリストの所属関係を管理する
- 初回リリースでは全メンバーを同じ権限として扱う
- 作成者だけがメンバー追加とリスト削除を行える

## 3. 機能要件

### 認証

- Google OAuth によるログイン
- ログアウト
- 自分のプロフィール取得

### リスト

- リスト作成
- 自分が所属するリストの一覧取得
- リスト名の変更
- リスト情報とメンバーの取得
- 作成者によるユーザー追加・メンバー除外
- 自分の退会
- 作成者によるリスト削除

### アイテム

- アイテム作成
- アイテム一覧取得
- アイテム名・数量の編集
- 完了・未完了の切り替え
- 未完了アイテムの手動削除
- 未完了を標準表示し、完了済みも切り替えて表示できる
- 作成日または更新日の新しい順で表示する

## 4. 初回リリースで行わないこと

- タグ・カテゴリ・検索・優先度・担当者
- 招待コードや招待リンク
- リアルタイム同期
- 完了アイテムの自動削除
- 通知、監査ログ、複雑な権限管理
- 購入履歴や分析

画面の再読み込みで最新状態を取得します。必要性が確認できた機能だけを後から追加します。

## 5. セキュリティ

- 認証は Supabase Auth のセッションを利用する
- 所属していないリストのデータへアクセスできない
- 認可は API と Supabase Row Level Security の両方で行う
- Supabase のサービスロールキーをブラウザへ渡さない

## 6. MVP で保留する判断

- 招待方法は、初回は作成者によるユーザー ID 指定とする
- 作成者と一般メンバーの権限分離は後回しにする
- リスト作成者の退会・譲渡フローは後から決める
