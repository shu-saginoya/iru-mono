# UI仕様

## 共通

- リスト・アイテムの作成、更新、状態変更、削除は楽観的UIで表示する
- 楽観的UIの操作中も、別のリストまたは別のアイテムの操作を受け付ける
- 同じ対象への重複操作は、処理完了まで受け付けない
- データ更新後は画面を再読み込みせず、該当表示を更新する
- APIエラーが発生した場合は変更前の状態へ巻き戻し、操作箇所の近くにエラー内容を表示する
- API成功後に返されたデータを正とし、楽観表示を実データで置き換える
- 他ユーザーによる変更はリアルタイム同期を導入するまで自動反映しない

## アイテム

- リストを開いたときは、完了・未完了を区別せず全件を取得する
- APIの1回あたりの取得上限を超える場合は、全ページを取得してから表示する
- 一覧取得では`status=all`を使用し、完了・未完了の表示切替ではAPIを呼び出さない
- アイテムは作成日時の新しい順で表示する
- アイテム一覧には未完了・完了済みを切り替えるセグメントコントロールを設置する
- デフォルトでは未完了のアイテムを一覧表示する
- 完了・未完了アイテムの表示切替はフロント側のフィルタで行う
- 未完了一覧では右下固定の追加ボタン（`+`）を表示する
- 追加ボタンを押すとアイテム追加モーダルを開く
- アイテムの編集ボタンを押すと、既存値を入力した編集モーダルを開く
- モーダルには商品名、数量、キャンセル、追加または保存を表示する
- 商品名は必須で、1〜255文字とする
- 数量は必須の整数で、1〜999とする。初期値は1とする
- モーダルを開いた直後に商品名入力欄へフォーカスする
- `Esc`、背景クリック、キャンセルでモーダルを閉じる
- 作成・編集・削除・完了切替のAPI処理中は、同じアイテムへの操作を無効にする
- 未完了アイテムの削除前には確認ダイアログを表示する
- 完了済みアイテムには削除操作を表示しない
- 入力エラーまたはAPIエラーが発生した場合はモーダルを閉じず、入力内容を保持してエラーを表示する

アイテムが0件の場合は、表示中の状態に応じて以下を表示する。

- 未完了: アイテム追加を促す
- 完了済み: 完了済みアイテムがないことを表示する

## リスト管理

- リスト作成フォームはサイドバーに配置する
- リスト設定からリスト名を変更できる
- リスト設定からメンバーの追加・除外ができる
- 一般メンバーはリストから退会できる
- 作成者はリストを削除できる
- 作成者自身の除外操作は表示または実行できない
- リスト削除または退会が成功した場合は、選択を解除して所属リストを再取得する
- リスト操作のAPIエラー時は、表示を変更前に戻して設定画面内にエラーを表示する

## リストサイドバー

- リスト一覧とリスト作成は同一のサイドバーに置く
- 幅が768px以上では、サイドバーを常に表示する
- 幅が767px以下では、初期状態でサイドバーを閉じる
- SPではヘッダーのメニューボタンから開閉する
- SPでリストを選択したらサイドバーを閉じる
- サイドバーの背景をクリックするとサイドバーを閉じる

## 前回のリスト

- ユーザーごとに最後に開いたリストIDをブラウザの`localStorage`へ保存する
- 保存値はユーザーが変わっても混ざらないよう、ユーザー単位のキーで管理する
- ログイン後、保存済みのリストIDが現在も所属リストに存在すればそのリストを開く
- 保存済みのリストが存在しない、または所属から外れている場合は、更新日時が最も新しいリストを開く
- リスト選択後に選択中のリストIDを保存する
- リストから退会またはリストを削除した場合は、そのリストの保存値を削除する
- 所属リストが0件の場合は、リスト作成を促す空状態を表示する
